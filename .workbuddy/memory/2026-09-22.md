## DouyinLiveRecorder 重构 + Electron 桌面端（承接上一轮，本轮补齐「桌面集成层」）

### 背景
上一轮已完成：`dylr/` 后端重构（平台注册表 / 配置元数据 / 任务状态机 / 标准库 HTTP+SSE 接口）
与 `electron/` 桌面端六个页面。本轮验收时发现：功能齐了，但**缺少让录制工具真正能挂机的那一层**。

### 本轮做的事

**1. 应用图标（原本一个位图资源都没有）**
- 新增 `electron/tools/make_icons.py`：纯标准库手写 PNG 编码器 + 距离场渲染，
  生成 `assets/icon.png(256)`、`icon.ico(16~256 多尺寸 ICO)`、`tray.png(16)`、`tray@2x.png(32)`。
- 字形复用应用内标题栏 logo 的「广播波 + 直播点」比例，配色取 CSS 变量（accent #5b8cff / live #ff4d5e）。
- 踩坑：① alpha 忘了 ×255 导致整图近乎全透明；② `simplified` 参数没传进几何函数，
  32px 托盘用了「四弧细描边」版，糊成一团；③ 左弧跨 ±180° 时 `atan2` 返回负角，
  区间判断失败导致下半段弧描边断裂（改为以 a0 为原点归一化到 [0,2π) 再比）。

**2. 系统托盘 + 关闭到托盘**（`electron/src/tray.js`）
- 原实现关窗即退出 → 挂机录制直接断，这是最影响实际使用的问题。
- 托盘：显示/隐藏、开始/暂停全部、打开录制目录、退出；悬浮提示实时显示「录制中 N · 等待 M」。
- 关闭窗口默认最小化到托盘（可在设置里关掉），并给一次气泡提示。

**3. 系统通知**（`electron/src/notifications.js`）
- 开播 / 录制结束（含时长体积）/ 任务异常 / 磁盘告警。
- 「要不要打扰」的判断放主进程（只有它能知道窗口是否前台/隐藏），渲染层只上报事件。
- 首次见到某任务只登记不通知（否则每次启动都狂弹）；同内容 5 秒去重。

**4. 偏好与窗口状态持久化**（`electron/src/prefs.js`，渲染层镜像 `renderer/js/prefs.js`）
- 存 `userData/desktop-prefs.json`，**不写进 config.ini**（那是录制核心的配置，会被 CLI 和上游读写）。
- 记住窗口几何；多显示器拔插后校验可见区域交集，避免窗口跑到屏幕外。
- `backgroundThrottling: false`：托盘状态下仍要按秒更新状态、及时弹通知。

**5. 设置页新增「桌面端」本地分组**

### 工具链踩坑（重要，环境相关）
- **宿主注入了 safe-delete shim**：`fs.rmSync`/`rm` 被劫持去走回收站，这里会抛

- **不要用 `taskkill` 杀进程**：会误伤用户自己跑的 python/electron，而且反复触发权限确认。
  抓图改为「独立启动 + 抓完自己退出」，脚本里彻底移除 taskkill。
- **给 Electron 传路径必须用 `D:/...`**：MSYS 的 `/d/...` 它不认，会导致进程静默退出、日志为空。
  脚本里统一用 `pwd -W`。
- 抓图模式（`--capture`）现在**不显示窗口**，可以随手跑而不打扰用户。

## 第二轮：用户报「双击了但没弹窗口」

### 真根因：.bat 的编码，不是 Electron
三个 .bat 都是 **UTF-8（无 BOM）+ `chcp 65001` + 文件里有中文**。
cmd.exe 按字节偏移逐行读批处理文件、用系统 ANSI 代码页（本机 936）解析；
中途 chcp 切代码页 → 行边界错位 → 中文被从中间截断当命令执行：

```
'锛?rem' 不是内部或外部命令
'鍦ㄥ畨瑁呮闈㈢渚濊禆锛圗lectron锛岀害' 不是内部或外部命令
'&&' 不是内部或外部命令
'f' 不是内部或外部命令
```

连 `&&`、`f` 都被当命令，控制流全乱 → Electron 从未被正确拉起。
**修法：GBK(936) + CRLF + 删掉 chcp**（转换脚本 `.workbuddy/tmp/convert_bats.py`）。
另加 `.gitattributes` 把 `*.bat` 钉成 `eol=crlf`（本仓库 autocrlf=true，
关掉时或在 Linux 检出会让 bat 变 LF，cmd 对 LF 批处理有 goto/标签解析问题）。

**判断口诀（很有用）**：用户说「双击没反应」先看 `logs/backend-console.log`
有没有新记录 —— 后端是 Electron 起来之后才拉起的。没有新记录 ⇒ 问题在 Electron
之前；有新记录 ⇒ Electron 起来了、崩在后面。

### 我自己引入的错误：GPU 自动重启
上一轮写的「GPU 崩溃 → `app.relaunch()` 带 `--disable-gpu` 重启」有两个问题：
1. **参数治不了病**。实测四组合（存活到 9 秒算成功）：
   无参数 ❌FATAL / `--disable-gpu` ❌FATAL / `--no-sandbox` ✅ / 抓图那组 ✅。
   真正的 FATAL 是 `gpu_data_manager_impl_private.cc GPU process isn't usable. Goodbye.`
   —— 原因是**受限环境里 GPU 进程建不起自己的沙箱**，跟显卡无关。
   `--disable-gpu` 完全无效。
2. relaunch 出来的新实例撞上 `requestSingleInstanceLock` 竞态、被自己锁死后静默退出
   —— 把失败藏起来比失败本身更糟。
现在只如实写 `logs/desktop-console.log`；保留手动的「关闭硬件加速」开关（不再自动写入）。

### 重要区分：这个 GPU 报错是我这边的沙箱环境造成的，不是用户机器
带 `--no-sandbox` 能跑、不带就跑不起来 ⇒ 本机/沙箱限制。用户正常桌面会话没这个问题。
验证方式：`MSYS_NO_PATHCONV=1 tasklist /v /FI "IMAGENAME eq electron.exe"`
拿到窗口标题（实测出现 `DouyinLiveRecorder` 即算通过）。
踩坑：Git Bash 里 `tasklist //FI ...` 会静默返回空，害我一度误判「进程没起来」。

## 第三轮：按要求加一个示范直播间，顺带挖出两个后端生命周期 bug

任务本身：`config/URL_config.ini` 加抖音「瑞幸咖啡」`https://live.douyin.com/945843973757`。
它当时正在直播（标题「秋山楂系列时令上新…」），但发现磁盘上**同一场直播被录了三份**。

### bug 1：孤儿后端 —— 父进程被异常结束，它还一直在录
Electron 崩溃 / 被强杀时优雅停止没机会执行 → 后端变孤儿继续录。
实测 **4 个后端 × 4 个 ffmpeg 同时录同一个直播间**，磁盘按倍数被吃满，界面无任何提示。
修法：Electron 传 `--parent-pid`，后端 `ParentWatch` 每 5s 确认一次
（Windows 用 `OpenProcess(SYNCHRONIZE)` + `WaitForSingleObject`，**句柄只开一次**
以免 PID 复用被误判；POSIX 用 `kill(pid, 0)`；拿不到信息按「活着」处理）。
实测：父进程存活（等 20s 跨 4 个周期）后端不受影响 ✔；父进程不存在 → 1s 内优雅退出 ✔。

### bug 2：`/api/quit` 是假退出（返回 200，进程不退）
只调了 `manager.shutdown()` + `httpd.shutdown()`：没 `server_close()` → 端口一直
LISTENING；也没通知主线程 → 进程挂着。所以桌面端每次退出都靠兜底升级到
SIGTERM / taskkill —— **而硬杀正是孤儿 ffmpeg 的根源**，兜底把假退出伪装成了正常工作。

修法：`ApiServer` 加 `on_quit` 回调只负责通知，停止顺序交给 `Service.stop()` 统一编排；
`stop()` 改用独立 `_stopped` 标记做幂等（**不能拿 `_stopping` 当判据** ——
quit 与看门狗都会先置位它以唤醒等待循环）；`--print-port` 路径补 `finally: stop()`。

- 清理了 3 个孤儿后端 + 3 个孤儿 ffmpeg（`Stop-Process` 按 PID 精确杀，没用 taskkill；
  用户的 my_ide Electron 未受影响）。最终只剩 1 后端 + 1 ffmpeg + 1 窗口。

  新逻辑下次启动才生效。

### 工具经验（本机环境）
- Git Bash 里 `tasklist //FI ...`、`tasklist //v` 会**静默返回空**；
  要用 `MSYS_NO_PATHCONV=1 tasklist /v /FI "..."` 才拿得到（还能看到窗口标题）。
- `wmic` 被安全策略禁用；`cmd.exe` 不能从 Bash 或 PowerShell 工具调用；
  PowerShell 工具的输出有时不回显 —— 用 `Set-Content` 写文件再 Read 最可靠。
- Bash 里 `A && B &` 会把整条 `&&` 链放进后台（`$!` 拿到的是子 shell）；
  只后台单个命令要用 `;` 分隔。
- 走不了 `taskkill` 时，PowerShell `Stop-Process -Id <pid> -Force` 可用。
